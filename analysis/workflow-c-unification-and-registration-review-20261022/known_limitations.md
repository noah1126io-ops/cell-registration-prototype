# 既知の制限と未検証の項目（2026-10-22）

## 1. アルゴリズム

- **画像探索の設定（tissue＋核map、zsum）は、031-6_2を見た後に選んだもの**です（2026-10-19のE2tnが6_2でUNIQUEになった）。6_2・8_6は開発中に見ているデータなので、画像探索の性能の独立した根拠にはなりません。独立したペアでの事前登録した評価が必要です。
- **031-8_6は未解決**です。画像探索・核探索ともAMBIGUOUSで、どの候補も核配置が偶然一致と区別できません（`global_search_diagnostics.md`）。これは「対応領域が存在しない」ことの証明ではありません。H&Eが031-7由来で、切片間の距離はUNKNOWN、蛍光に純粋な核チャンネルはありません。
- **Runner経由の実行時間**：031-8_6（HE Fixed）は、UIからの実行で3,219 s（54分）かかりました（同時に他のジョブも動いていたため）。Slurmの上限1.5時間の範囲内ですが、余裕は大きくありません。
- **画像探索は遅い**です。HE Fixedでは、画像探索だけで約12分かかります（2層、2,100 µmの視野、4 µm格子）。自動実行全体では、HE Fixedで約25分、IF Fixedで約15分です（CPU 4コア）。粗い探索（16/8 µm）にすれば約1/4になりますが、事前に決めた設定ではないため既定にしていません。
- **採択規則の限界**（2026-10-20の難易度実験）：共有される核が約15%以下だと、正しい位置合わせでも≤3 µm ≥ 0.25に届きません。規則は変えていません。
- **注釈を使った探索**（ROI・除外・初期位置・対応点）は、合成データの単体テストと031-8_6のROI 1件（`cache/wf_assisted_86.json`）でしか確かめていません。注釈が探索をどれだけ改善するかは評価していません。
- **反転（reflection）**は、核探索・画像探索とも既定で探索しません（2026-10-19の設定どおり）。
- **局所変形**は扱いません。similarityの探索と、重なり領域でのaffine ICPだけです。

## 2. Workflow C / D との接続

- Workflow Cの画面で研究結果をglobal affineに使えるのは、研究Runnerで作った**採択済み・完全自動**の結果だけです。Workflow Cの画面で研究Workflow C自体を実行することはできません。CPUで約15〜25分かかるため、Slurmの研究Runnerから実行します。
- Workflow Cの画面でアップロードした核座標が研究結果と同じものかは、中央値NN ≤ 10 µmでしか確かめていません。完全一致（fingerprint）での確認は、Workflow D用の書き出し（`workflow_d_bridge`）だけで行っています。Workflow Cのアップロード（.npy、px）と研究入力（CSV × spacing）では、浮動小数の表現が変わるためです。
- Workflow D用の書き出しはaffineだけです（fine stageなし）。研究結果にfine stage（density flow など）を続けたい場合は、Workflow Cの画面で研究global affineを選んで実行します。
- 研究結果からWorkflow Dのsessionへの自動の受け渡しは、意図的に作っていません（ファイルの書き出しのみ）。

## 3. Web UI

- 双方向のviewerは、Streamlitのcustom componentのプロトコル（postMessage）を直接使っています（npmのbuildなし）。Streamlit 1.62で確認しました。将来のStreamlitでプロトコルが変わると、クリック操作（対応点・ROI・候補の選択）が動かなくなる可能性があります。その場合も、表示とPythonの入力欄（手動調整など）は使えます。
- 候補表の行の選択（`st.dataframe` の選択）は、ブラウザE2Eでは確かめていません（canvas描画の表で、行を自動でクリックしにくいため）。地図上のクリックによる選択は確かめています（Test K）。
- 対応点のMoving座標は、**表示中の変換の逆写像**で求めます。表示中の変換が大きく間違っている場合は、Moving側の構造を正しくクリックすれば正しい座標になります。ただし、重ねて表示されたMoving画像の上でクリックする必要があります。
- 研究ストアはNFS上のSQLiteです。書き込むのはStreamlitのプロセスだけという前提で、ファイルロックと1トランザクションの書き込みにしています。複数のサーバープロセスから同時に書く使い方は想定していません。
- ストアは追記のみです。誤って保存した評価や注釈は削除できず、`supersedes` で新しい行に置き換える形になります。UIからの置き換え操作は、まだ注釈の一覧からはできません（APIのみ）。
