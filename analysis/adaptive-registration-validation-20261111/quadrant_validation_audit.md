# 象限一致チェックの監査（registration_core 1.2、2026-11-11）

- 対象のコード：`src/registration_core/workflow.py` の `quadrant_consistency`、`QUADRANT_RULE`、`_decide_adjacent`。
- 監査に使ったデータ：
  - `quadrant_audit_all_candidates.csv`：本番では image#0 だけを調べるが、今回は全画像候補に実行した。
  - `quadrant_global_audit.csv`：独立性を高めた別の方式。
  - `validation_rows.csv`：判定の結果。
- **注意**：この監査に使ったデータはすべて、開発に使った 031-6_2 と 031-8_6 から作った派生ケースで、独立した検証ではない。
- **4/4 一致は、正解の証明ではない。** 以下の結果は、このことを具体的に示している。

## 要約
1. 象限チェックは「候補の周辺で、4 つの部分視野が同じ位置に戻るか」を調べる**局所的な安定性の検査**である。
   - 対応領域が正しいことを独立に確かめる検査ではない。
2. 誤った候補（正例ケースの中の誤った候補 56 個、負例ケースの候補 73 個。occ+cleft と tissue+nuclear の両方を合わせた数）のうち、3/4 以上で合格したのは **1 個**（`N6_2_IFmirror` の image#0、3/4）。
   - この候補は、物理的にありえない姿勢（鏡像の IF）だった。
   - 6_2 を来歴どおり DIFFERENT（隣接切片）として扱うと、本番の規則でも **`TISSUE_LEVEL` になる（誤採択）**。
3. 正しい候補でも不合格になる例が多い（図 2）。
   - 部分重なり（`HEpartial60`：2/4）と小視野（`IF500`：1/4〜2/4）では、正しい位置の候補が棄却された。
4. 象限ごとに全域を探索するより独立な方式は、誤りをすべて止めたが、正しい候補もほとんど通らなかった（8_6 は 0/4、6_2 は 2/4）。採択ルールとしては使えない。

## 監査の 6 項目

### 1. 探索範囲をどう制限しているか
- `QUADRANT_RULE` の設定：
  - 回転は候補 ±4°（1° 刻み）
  - スケールは 0.97 / 1.00 / 1.03
  - 並進は候補 ±100 µm（`window_um`）
- fixed 側は、象限の投影先 + (100 µm + 象限の対角線の半分 + 20 µm) の範囲に切り出す。
- 合格条件は、位置の差 ≤30 µm かつ回転の差 ≤2° の象限が、4 つのうち 3 つ以上あること。
- 窓が候補を中心にしているので、「候補の周りに局所的な最大点があるか」しか判定できない。
  - 誤った候補も、主探索で見つかった局所的な最大点なので、同じ性質を持ちうる。

### 2. 主探索と同じ特徴量やバイアスを共有しているか
- **共有している。**
  - 特徴量（`cfg.image_feature` = occ+cleft）、解像度（`res_fine` 4 µm）、スコア（masked NCC → z の合計）がすべて主探索と同じ。
  - 違うのは、使う空間範囲（IF の 1/4）だけ。
- そのため、occ/cleft がたまたま似た構造に反応する場合、全視野と象限が**同じ方向に**だまされる。
- `N6_2_IFmirror` がその例：image#0（θ=210°）の cleft の z は 11.5。4 象限のずれは 10 / 15 / 7 / 9 µm で、すべて近い。

### 3. 間違った候補でも象限が一致する条件
- 実際に起きた例は `N6_2_IFmirror` の 1 件。
- 6_2 の IF 視野は、組織の外縁と空白を多く含む（`boundary_info` 0.59、8_6 は 0.15）。
  - 大きなスケールの構造（外縁、太い間隙）は、象限に分けても 4 つすべてに残る。
  - こうした構造は、鏡像にしても局所的にはよく重なりうる。
- この候補は margin 0.215 で UNIQUE、重なり率 1.00 だった。主探索の判定だけでは止まらない。
- この候補の核の近接率は 0.068 で、null の 0.035 の約 2 倍だった。同一切片用の基準（≥0.25 かつ null の 3 倍以上）なら止まる。
  - ただし、隣接切片のゲートでは、核の近接率は判定に使わない。
- 一般化すると、象限一致が誤って成立しやすいのは次の条件のとき：
  - 視野全体を貫く大きな構造が支配的なとき（外縁、太い間隙、管腔）
  - 象限ごとの独自の構造（細かい間隙）が弱いとき

### 4. 対応領域が部分的にしかない場合
- **正しい候補でも棄却される（偽陰性）。**
- `P8_6_HEpartial60` と `P6_2_HEpartial60` は、どちらも 2/4 だった。
  - HE の外に出る 2 象限は「quadrant maps mostly outside the fixed field」として、合格しなかったと数えられる。
  - 「判定できない」とは区別されていない。
- 重なりが 60% の場合、規則上 3/4 には届かない。
- 部分重なりが普通にある実データ（FOV が異なる、部分的に重なる）では、規則が構造的に不利になる。

### 5. 組織が少ない象限の扱い
- 組織の量による条件や重み付けはない。
- 組織がほとんどない象限でも NCC の最大点は出るので、偶然一致する可能性も、偶然外れる可能性もある。
- 小視野（`IF500`、象限 250 µm 角）では、正しい候補でも 1/4（8_6）、2/4（6_2）しか合格しなかった。
  - 象限の情報量が足りない。
- 改善案：組織の割合や cleft の強さが閾値に満たない象限は「判定不能」とし、判定に使える象限の中での割合で判定する。
  - これは**提案**であり、今回は採択規則を変えていない。

### 6. 1 つの象限が他の象限と似ている場合
- 反復性（cleft の自己相関の最大値）は、8_6 で 0.065、6_2 で 0.109 と低い。
- このため、今回のデータでは、反復構造に対する安定性を確かめられていない。
- 反復が強い組織（例：規則的な腺管、小葉構造）では、次の 2 つが同時に起きると考えられる。
  - 主探索の margin が小さくなる（AMBIGUOUS で止まりやすい。これは安全側）。
  - 象限の窓 ±100 µm の中に、反復の周期で別の最大点ができる。
- 確かめるには、反復性 > 0.3 の実データが必要（`v1_roadmap_recommendations.md` の「必要データ」を参照）。

## 独立性を高めた方式との比較（`quadrant_global.py`）
- 各象限で、HE 全域を通常の画像探索で調べ、全視野の image#0 と同じ位置（≤30 µm、≤2°）を選ぶかを見た。
- 候補の位置を窓に使わないので、主探索の結果には依存しない。ただし、特徴量は同じ。

| ケース | 一致した象限 | 象限ごとの探索の判定 |
|---|---|---|
| P8_6_orig（正例） | 0/4 | 4 つとも AMBIGUOUS（約 960〜1230 µm 離れた位置を選ぶ） |
| P6_2_orig（正例） | 2/4 | Q3 だけ UNIQUE |
| N8_6_IFmirror | 0/4 | AMBIGUOUS |
| N6_2_IFmirror | 0/4（Q3 は 14 µm だが回転差 −2.0° で境界上） | AMBIGUOUS |
| Ncross ×2 | 0/4 | AMBIGUOUS |

- **8_6 では、4 分の 1 の視野（約 513 µm 角）だけでは、全域から位置を決められない。**
  - そのため、この方式は感度が低すぎて、採択ルールには使えない。
- ただし、この方式は**鏡像の負例を止めた**。局所の象限チェックとは違う情報を持っていることを示している。
- 1 ケースあたり 4 回の全域探索（約 4 × 14 分）が必要で、計算量も大きい。

## 提案（本番の採択規則は変えていない。次の検証の候補）
1. **判定を 3 値にする**：視野外の象限や、組織の少ない象限は「判定不能」とし、合格とも不合格とも数えない。部分重なりで正しい候補が棄却される問題への対策。
2. **核の情報を補助的に使う**：隣接切片でも、核の近接率と null の比を「整合する／しない」として記録し、表示する。
   - 鏡像の例では比が約 2 で、正しい 8_6 の約 1.4 と区別できない。合否には使えないが、説明の材料にはなる。
3. **探索手段どうしの一致を、独立した証拠の 1 つとして記録する**（画像の候補と点群の候補の距離）。
   - 隣接切片では、点群探索が失敗するのが普通（8_6 ではどの条件でも 1000 µm 以上ずれる）。そのため、一致しないことを否定の根拠にはできない。
   - 一致した場合（6_2 では 4〜6 µm）だけ、肯定の証拠として扱う。
4. **TISSUE_LEVEL を自動で採択しない現在の方針を維持する**（今回の誤採択の例を根拠にする）。人の目視確認を前提にする。
5. 象限の窓（±100 µm）が候補を中心にしていること自体は避けられない。そのため、**「象限一致は局所的な安定性の指標」と UI に明記する**。
