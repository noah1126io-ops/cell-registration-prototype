## 3. 追加したデータ構造
- **アルゴリズムの状態**（変更なし）：matched / ambiguous / unmatched。`auto_correspondence.csv` にあり、一度だけ書き込み、sha256 で保護している。
- **人のレビュー状態**（`REVIEW_STATUSES`、アルゴリズムとは別に保存）：

| 状態 | 意味 | 対応先 |
|---|---|---|
| `unreviewed` | 未レビュー（判定を記録していない。アルゴリズムの結果は人の結果として扱わない） | なし |
| `confirmed_match` | 対応確認（支持、または候補・任意の IF 核に変更して確認） | IF の ID を保存 |
| `not_identified` | 未特定（対応する核はあり得るが特定できない） | なし（元の対応先は `held_if_index` に残す） |
| `absent` | 非観測（IF 切片の観察範囲に対応する核が見えない） | なし。`scope.absent_in = "IF"`。**コメントは必須** |
| `uncertain` | 判断不能（画像の品質・セグメンテーション・候補の競合など） | なし |
| `released` | 判定を記録せずに対応を外した（11-17 の「除外」「未確定」） | なし |

- unmatched を自動で非観測に変えることはない。人が判定を記録した核だけが、人の状態を持つ。
- 「未レビューに戻す」（`reset`）で、判定を取り消せる。
- **補助タグ**（`REVIEW_TAGS`）：H&E 側のセグメンテーション異常、IF 側のセグメンテーション異常、核の分割・結合の疑い、画像の品質、候補の競合、観察範囲の端・外、位置合わせの誤差の疑い。
- **操作の記録**（履歴に追記するだけ）：
  - 操作・対応先・使用者・日時・コメント・タグ・元の推定の値。
  - 判定のときは `scope` も記録する。中身は、元の切片（HE）と対象の切片（IF）、確認した範囲（µm）、IF の画像を使ったか、IF の撮影範囲の内側か、IF の輪郭があったか、アルゴリズムの状態。
- **レビューのコンテキスト**：使ったセグメンテーションの識別子（ファイル・sha256・結合キー・整合性の集計）。レビューの JSON に保存する。
- **評価用の表**（`review_annotations.csv`、1 核 1 行）：
  - 識別：サンプル・auto_id・review_id・版、元の切片と対象の切片、元の細胞 ID。
  - アルゴリズム：状態・top1・スコア（輸送量の割合、B2 の確率）。
  - 人のレビュー：状態・対応先の ID、対応先のアルゴリズム上の順位・輸送量の割合・距離、top1 と一致したか、元の対応先、判定。
  - 記録：日時・使用者・コメント・タグ、非観測の対象切片。
  - 品質：衝突、両側の輪郭の状態、両側のセグメンテーションの sha256。
- **集計**（`review_metrics.json`）：
  - レビュー状態ごとの件数（全体、およびアルゴリズムの状態ごと）。
  - algorithm matched の精度（判断不能と判定なしの解除は、分母に入れない）。
  - 対応確認のうち、アルゴリズムが同じ対応を見つけていた割合。
  - 未特定＋非観測の率、非観測の率、判断不能の率。
  - 2 つのレビューの一致（`review_agreement`）：状態の一致率、状態と対応先の一致率、Cohen の κ。

## 4. 画面と操作の手順
1. 自動推定を選ぶ（11-17 と同じ）。
2. 「セグメンテーション（核輪郭）の整合性」の表を確認する。座標系が合わない場合や、中心点と輪郭が一致しない場合は、警告を表示する。
3. 全体ビューアー（IF frame）。
   - 拡大すると、核輪郭が薄く表示される。さらに拡大すると、細胞 ID が表示される。
   - 輪郭・ID・中心点は、それぞれ表示を切り替えられる。輪郭の濃さも変えられる。
   - 選択した H&E 核（黄色）、その候補（白の破線）、クリックした IF 核（水色）の輪郭は、常に強調する。
   - 核の色は、レビューの状態を表す。
4. H&E 核をクリックする。
   - パネルに、アルゴリズムの状態と人のレビューの状態を、並べて表示する。
   - **左右比較**：左に H&E、右に IF を、どちらも未変形の元画像と、その切片の座標で表示する。
     - 拡大範囲は 30 / 60 / 120 µm。
     - 左右それぞれでズーム・パンでき、Global Affine で位置を同期することもできる。
     - 周辺の核は薄く表示し、選択した核・比較中の候補・現在の対応先を強調する。
     - 右には、Global 変換による予測位置も表示する。
   - 「比較する候補」で候補を切り替えられる。順位・距離・輸送量の割合・graph support を表示する。
5. 判定を記録する（1 回のクリック）：
   - 「✔ この候補で対応確認」：比較中の候補で確定する。
   - 「未特定」「非観測（IF）」「判断不能」。
   - 「対応を解除」「未レビューに戻す」。
   - コメントと補助タグを付けられる。「記録したら次の未レビュー核へ進む」をオンにすると、次の核が自動で選ばれる。
6. 取り消し・やり直し・保存（新しい版）・保存済みのレビューの再読み込み・レビューの JSON・評価用の表（CSV）の出力。表は、変位場を計算しなくても出力できる。

## 7. 未解決の制約
- **実際のブラウザでのクリック・ズーム・同期は、自動では確認していない**（ヘッドレスブラウザは使えない）。JS は Node で、ズームの段階に応じた表示（LOD）・画面外の省略・ID の表示数を検査した。Python 側は AppTest で、見た目は matplotlib の図で確かめた。開発サーバー 8511 で確認してほしい。
- レビューの起点は **H&E 核だけ**（H&E → IF）。IF 核を起点とした判定（H&E 切片に核がない）は、まだ記録できない（表には方向の列を用意してある）。
- 一つの H&E 核の対応先は 1 つ（一対一）。分割・結合は、補助タグで記録するだけ。同じ IF 核への複数の対応は検出して表示するが、自動では解決しない。
- 全体ビューアーには、自動推定の ROI（＋30 µm）の輪郭だけを送る。数万の核を含む ROI では、転送する量が大きくなる。そのときはタイルごとの遅延読み込みが必要になる（未実装）。
- 未特定・非観測・判断不能の核は、対応先を持たないので、手動修正後＋RBF の変位場のアンカーにならない（既存の「除外」と同じ扱い）。
- 精度の集計は、人のレビューを基準にしたもので、生物学的な正解ではない。分母は、レビューした核だけ。
- 2 つの閾値は、実データ（最大 0.63）を見て決めたもので、検証はしていない。
  - 重心のずれの警告：等価な半径の 1.0 倍。
  - 座標系の不一致：中心点が輪郭の内側にある割合が 50% 未満。
