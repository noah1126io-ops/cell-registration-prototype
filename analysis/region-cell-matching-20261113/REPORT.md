## 0. 要約
- **Phase 1（C1 の上位 k 件を Graph/UOT/B2 で並べ替え）では、救済はほとんどできなかった。** 主な原因は、正しい領域が候補に入っていないこと（候補生成の再現率）である。
  - 合成 39 件で救済 0 件、悪化 0 件。
  - 実データ由来 16 件では、候補をまとめた場合は救済 0 件。points 側の候補だけで見た場合に救済 1 件（P6_2_IFhalfL）。ただし、この 1 件は既存の C3 の近接（`le_3um`）でも同じように救えた。
  - 事前指定の支持条件を満たさないときは、C1 の 1 位を残す（実効規則）。この規則では、悪化も誤った支持も 0 件だった。条件を使わずに順位だけで置き換えると、8_6 系で 4 件悪化した。
  - 候補を 30 件に広げても（K30、21 件）、救済は 1 件だけだった（C3 でも救える）。C1 の計算時間は 5.5 倍になった。
- **候補ごとの「正しい領域か」の識別力は、既存の C3 と同程度だった。** 合成データでの AUC は、主指標が 0.972、C3 の `le_3um` が 0.977。Graph/UOT を足しても、独立の新しい情報にはならなかった。
- **周期的な組織では誤った支持の危険がある。** repeat=1 では、誤った領域でも B2 の採択率が 0.62 に達した（真の ID との一致は 0）。mirror decoy では差し引けない。
- **Phase 2（核対応から局所変形）**：
  - Global の変換を既知とした合成データでは、B2 の対応をアンカーにした linear RBF（C）が最良だった。SYN-FIELD 50 件で、EPE の中央値は Affine 2.92 µm、UOT conservative（D）2.29 µm、C 0.89 µm。独立ランドマークの TRE も、D の 2.26 µm に対して C は 0.89 µm。
  - ただし、変形がほとんどない合成データ（SYN-C1）では、C はアンカーに使っていない核の TRE を Affine より悪化させた（16 敗 6 勝）。D は 22 勝 0 敗だった。
  - 実データの隣接切片（8_6）では、独立ランドマークの残差は改善しなかった（Affine 21.53 µm に対し、D 21.24 µm、B′ 21.51 µm）。
- **誤った領域でも、既存の監査は B′ / D の局所変形を通してしまう。** REAL-D の誤った候補 27 件のうち、B′ は 23 件、D は 16 件で適用された。C / E は B2 のアンカーが足りず、0 件だった。
- **Workflow C への統合は勧めない。** 研究タブ（既定で無効）で、診断の表示として残す。

## 4. 実験 C-K30（候補を 30 件に広げる）
- 設定の上書き `WorkflowConfig.search={"n_fine": 30}` だけで、細かい段階に進める候補を 30 件に広げた。7 条件 × seed 3 個 = 21 件。コードと本番の既定値は変えていない。
- 結果は `candidate_recall_k30.csv` と `rerank_summary.csv`（`K30_` で始まるケース）。

| 指標 | 既定（6 件） | K30 |
|---|---|---|
| 1 ケースあたりの候補数（C2 を通ったもの） | 2〜6 | 17〜30 |
| 候補の中に正しい領域があるケース | 6 / 21 | **9 / 21** |
| C1 の 1 位が正しい | 5 / 21 | 5 / 21 |
| 主指標の 1 位が正しい（支持の条件なし） | — | 7 / 21 |
| C3 `le_3um` の 1 位が正しい | — | 6 / 21 |
| 実効規則（支持されたときだけ置き換え）で正しい | — | **6 / 21**（救済 1、悪化 0、誤った支持 0） |
| C1 の計算時間の中央値 | 360 秒 | **1967 秒（約 5.5 倍）** |

- 候補に新しく正解が入ったのは、次の 3 件。
  - repeat=0.5 seed 1003（2 位）
  - grid ratio=0.25 ＋ ns=0.85 の seed 1001（11 位）と seed 1003（2 位）
- **救済できたのは repeat=0.5 seed 1003 の 1 件だけ**（主指標 0.619、2 位 0.014 で支持された）。この 1 件は、既存の C3 `le_3um` の順位でも救えた。
- ns=0.85 の 2 件は、正しい候補の B2 の採択率が低く（共有される核が 15% しかない）、支持されなかった。主指標だけで選ぶと seed 1003 は正しかったが、2 位との差は 0.001 しかなく、偶然の範囲である。
- repeat=0.8 / 1、overlap=0.3、absent では、30 件に広げても正しい領域は入らなかった。点群探索の粗い段階の時点で、正解が落ちている。
- K30 でも、repeat=1 の誤った候補の主指標は 0.638 と 0.627 だった。差が 0.05 に届かなかったので、支持はされなかった（§2.1 と同じ危険）。
- まとめ：
  - 候補を広げると、候補に正解が入る割合は少し上がる（6→9 / 21）。ただし計算時間は 5.5 倍になり、救済は 1 件だけで、その 1 件は C3 でも救える。
  - 候補生成の失敗の多くは、粗い段階の失敗か、組織の繰り返し構造による本質的なあいまいさによるもので、n_fine を増やすだけでは解決しない。

3. **Baseline の維持**

   - 実データの B0 / B1 / B3 / B2 が 10-14 と完全に一致。SYN-FIELD の D が 09-11 と一致（test_results.md）。
4. **Top-k による救済の可否**
   - ほぼできない。合成データでは救済 0 件（39 件）、実データ由来では points の候補だけの場合に 1 件（P6_2_IFhalfL）。その 1 件は既存の C3 でも救えた。
   - 救えない主な理由は、正しい領域が上位 6 件に入っていないこと（C1 の 1 位が誤る 16 件中 15 件）。
   - 候補を 30 件に広げると（K30、21 件）、候補に正解が入るケースは 6 件から 9 件に増え、救済は 1 件（repeat=0.5 seed 1003）だった。その 1 件も C3 で救えた。C1 の計算時間は 5.5 倍になった（§4）。
5. **UOT による細胞対応の改善**
   - 候補の選び方による改善はない（救済がないため、選ばれる候補が変わらない）。
   - 正しい領域では、B2 の対応の precision は 0.95（B0 は 0.81）。誤った領域では、B2 は matched をほぼ出さない（B0 は 150 件前後の誤った対応を出す）。これは 10-14 の B2 の性質であって、今回の統合によって新しく得たものではない。
6. **改善の原因**
   - Phase 2 で C が良いのは、アンカーの質（適合率 0.47 → 0.85）による。変形場（linear RBF）は B′ と同じである。
   - Phase 1 の候補の識別力は、既存の C3 の近接と同程度（AUC 0.972 と 0.977）。B2 の採択は、その姿勢で核の配置が局所的に一致することを測っているだけで、領域の正しさの独立した証拠ではない。
7. **局所変形は、独立指標で Affine より改善したか**
   - 合成データで Global が正しいときは、改善した（SYN-FIELD：EPE 2.92 → C 0.89 µm、独立ランドマーク TRE 3.06 → 0.89 µm）。
   - ただし、変形がほとんどないデータでは、C は Affine を悪化させる（SYN-C1 で 16 敗）。安定して改善したのは D（22 勝 0 敗）だが、改善幅は小さい。
   - 実データの隣接切片 8_6 では、独立ランドマークの残差は改善しなかった（21.53 → 21.24 µm、`T_search` では悪化）。
8. **誤対応と誤変形の危険**
   - 周期的な組織では、誤った領域で B2 が 6 割以上を matched にする（誤った支持の手前まで行った）。
   - 既存の監査は領域の正しさを見ないので、誤った領域でも B′ / D の局所変形が適用される（実データ由来の誤った候補 27 件中 23 件と 16 件）。
   - C は変形が小さいときに過剰適合する。unmatched の核も 2.5 µm ほど動かす。
   - UOT は 6_2 で数値的に失敗する（Affine に戻している）。
9. **実データで確認したことと、合成データだけで確認したこと**
   - 実データで確認したこと：
     - 8_6 系では支持されない（誤った支持なし、実効規則で悪化なし）。
     - P6_2 系の正しい候補は強く支持される（ただし 6_2 の切片関係が矛盾しているので、同じ細胞の証明ではない）。
     - 局所変形の適用と棄却の様子。8_6 のランドマークの残差が改善しないこと。誤った候補にも B′ / D が適用されること。
   - 合成データだけで確認したこと：救済の可否、核対応の precision と recall、EPE と TRE の改善、周期的な組織での危険。
   - 実データでの細胞対応の正しさは、評価できる正解がないので主張しない。
10. **Workflow C に統合する価値**
    - 今の形では統合を勧めない。理由は次の 3 つ。
      - 救済がほぼない。
      - 識別の情報が既存の C3 と重なる。
      - 隣接切片（実際に使う主なケース）では、核対応が期待できない。
    - 価値があるのは次の 2 点。
      - 「同じ切片で、領域が正しいときの局所変形のアンカー」としての B2（C）。ただし、変形量が小さいときの悪化と、誤った領域での適用の危険があるので、領域の検証の後に条件を付けて使う研究課題として残す。
      - Explorer の研究タブ（既定で無効）での診断の表示。
    - Workflow D には何も送っていない。research.sqlite には書き込んでいない。
