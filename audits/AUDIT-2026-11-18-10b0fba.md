**指摘 1：既知の誤採択リスクが残る — 高（観点1・4）**

- **事実：** INTENT は、`031-6_2` について manifest の別切片情報と `registration_core/workflow.py` の `infer_section_relation` による `same` 推測が衝突し、`ACCEPTED` になっていると記録しています。A1/A8 はユーザー承認待ちです。また、鏡像負例が隣接切片の規則で `TISSUE_LEVEL` まで通ること、`POINT_ONLY_FALLBACK` が3状態契約外に存在することも既知です。今回の差分一覧に `registration_core` の変更はありません。
- **推測・影響：** これらが今回解消された根拠はなく、従来の誤採択または状態解釈のリスクが継続していると扱うべきです。今回の差分自体がそれらを悪化させた証拠はありません。
- **改善案：** 承認後、明示メタデータを優先し、UNKNOWN／CONFLICT では自動採択を保留する A1 と A8 の回帰テストを実施する。鏡像負例と契約外状態も含め、Workflow D への受け渡し条件を3状態契約に照らして確認する。

**指摘 2：レビュー済み変位場と出力の既知の信頼性問題が未解消 — 高（観点1・4・6）**

- **事実：** 前回監査では `cell_review.py` の `Review.pairs()` 経由で未レビューの自動対応が「手動修正済み」変位場のアンカーに残る問題と、`review_metrics()` の accuracy の分母に `not_identified` が含まれる問題が高とされました。前々回には、レビュー変更後も古い field/image を出力できるトレーサビリティ問題が高とされています。提示された `cell_review.py` 差分は主に `cell` 記録と注釈列の追加であり、これらの修正は示されていません。
- **推測・影響：** 解消の証拠がないため、手動確認済みと誤認したアンカー、誤解される精度値、旧レビューに由来する出力が引き続き生じ得ます。今回のテストで変更前との数値一致が示されたことは、既知の問題の解消を意味しません。
- **改善案：** 確認済み対応だけを使う変位場の条件を明示し、未特定を分けた指標の分母を定義する。出力にレビュー版・入力ハッシュを結び、変更後の古い field/image を無効化または明示する。それぞれ回帰テストを追加する。

**指摘 3：細胞輪郭の記録と判定時の表示の対応は一部未確認 — 中（観点1・4）**

- **事実：** `cell_review.py` の `Review.apply()` は `cell_segmentation.validate_annotation()` の結果を操作記録に付け、`Review.to_json()` は `cell` があれば schema `/3` を選びます。提示差分では `cell` を核対応の選択や変位場の計算に使う変更は見当たりません。`cell_review_ui.py` の `_nucleus_panel()` は判定ボタンの前に `active` または現在の IF 対応から `cell` を作りますが、`_cell_review_inputs()` と各判定ボタンの細部は提示されていません。比較用に複数方式を重ねられる一方、保存対象はどの表示と対応するかを提示部分だけでは完全に追えません。
- **推測・影響：** 判定時の IF 対象と記録した細胞 ID、または実際に見た重ね表示と保存した方式が食い違う可能性は排除できません。実際に食い違ったとは確認できていません。輪郭の「妥当」と核対応の「確認」は別の評価ですが、判定と同時に入力するため混同の余地もあります。
- **改善案：** 判定に渡す IF 対象から、その操作の `cell` を確定することを確認する。主表示・比較表示の方式とハッシュ、対象 ID を判定時の表示と照合するテストを追加する。UI と出力で「輪郭の信頼度は核対応の正しさを示さない」と明示する。実ブラウザでの操作も確認する。
