## 指摘一覧

### 1. 【高】切片関係のメタデータ競合が判定へ反映されず、031-6_2 が自動採択され得る

**根拠**

- `workflow.py`：`WorkflowConfig.section_relation`、`infer_section_relation()`、`run_workflow()`、`refine_and_validate()`、`decide()`
- `tests/test_registration_core.py`：234〜242行、特に239〜240行
- `RESEARCH_STATUS.md`：§2、§4.1
- `INTENT.md`：切片関係の明示メタデータ管理、既知リスク1

**事実**

`WorkflowConfig.section_relation` の既定値は `"auto"` であり、`infer_section_relation()` はファイル名だけから切片関係を推測する。manifest や `provenance.same_section` を受け取る引数も、競合を検出する処理もない。

031-6_2 が ACCEPTED になる経路は次のとおりである。

1. 既定設定で `run_workflow()` が `infer_section_relation()` を呼ぶ。
2. HE ファイル名から `"031-6"`、IF ファイル名と sample_id からも `"031-6"` を得る。
3. 両者が一致するため `"same"` を返す。提示テスト239〜240行も、この挙動を期待している。
4. `refine_and_validate(..., relation="same")` では、隣接切片用の「ICP は診断のみ」という制限が適用されず、核配置の評価を採択判定に用いる。
5. `decide()` は隣接切片用分岐へ入らず、各探索について `UNIQUE` と `geometric_pass` を判定する。
6. 画像探索だけが基準を満たす場合、または複数の合格探索が同じ領域を指す場合、`status="ACCEPTED"` となる。自動実行なら `accepted=True` となる。
7. `run_workflow()` は transform にもその accepted 値を記録する。橋渡し側には切片関係を再確認する処理がないため、他の条件も満たせば Workflow D へ渡せる。

ここで `decide()` が返す `"CONFLICT"` は、合格した探索どうしが異なる領域を指す場合の状態である。manifest とファイル名の**来歴上の CONFLICT とは別物**であり、後者を防御していない。

**事実と推測の区別**

6_2 が ACCEPTED、値が1.9078 µmであることは資料の申告であり、本監査では再現していない。実際にどの探索が合格したかも artifact 不在のため確定できない。一方、上記の採択経路がコード上存在することは確認できる。

また、`same_section=false` は同一切片でないことを示すが、それだけでは「隣接」か「異なる切片」かを確定できない。修正後に必ず TISSUE_LEVEL となるわけでもなく、切片関係の確認と象限チェック等の合格が必要である。

**修正案・改善案**

明示メタデータを判定の入力とし、ファイル名推測は比較用のヒントとして記録する。来歴競合を探索間 CONFLICT と区別して保存し、未解決時は自動採択と Workflow D 接続を保留する。6_2 の修正後の判定は、確認済みの切片関係と適用規則の結果から決める。

### 2. 【高】UNKNOWN・未定義の切片関係が同一切片用規則へ流れる

**根拠**

- `workflow.py`：`SECTION_RELATION_TEXT`、`WorkflowConfig`、`infer_section_relation()`、`decide()`、`refine_and_validate()`
- `INTENT.md`：明示メタデータによる切片関係管理、既知リスク1

**事実**

ファイル名を解釈できない場合、`infer_section_relation()` は `"unknown"` を返す。表示文言も「不明（同一切片として扱う）」である。

`decide()` が特別扱いするのは `"adjacent"` だけであり、`"unknown"` は同一切片用の核配置規則へ進む。明示設定も値の検証なしで返されるため、`"conflict"`、`"different"`、誤記などの文字列も同じ分岐へ入る。

したがって、核配置基準を満たせば、切片関係が未確定でも `accepted=True` になり得る。

**事実と推測の区別**

自動採択可能な分岐の存在はコード上の事実である。UNKNOWN や未定義値による実際の誤採択例は、提示資料からは確認できない。

**修正案・改善案**

切片関係の許容値を検証し、`same / adjacent / different / unknown / conflict` を明示的に分岐する。UNKNOWN・CONFLICT は安全側で自動採択を保留し、異なる切片の扱いも事前に規定する。

### 3. 【高】隣接切片用判定に、既知の鏡像負例を排除する防御がない

**根拠**

- `workflow.py`：`_decide_adjacent()`、`quadrant_consistency()`、`_local_search()`
- `RESEARCH_STATUS.md`：§4.2
- `INTENT.md`：既知リスク2

**事実**

隣接切片用の合格条件は、画像探索が `UNIQUE` で、象限チェックが合格することである。候補の chirality や変換行列の行列式を理由に拒否する条件はない。

さらに `_local_search()` は初期行列の行列式が負なら `"reflect"` を選び、その chirality のまま局所探索する。したがって象限チェックは、鏡像候補を独立した向きの根拠で否定する仕組みにはなっていない。

RESEARCH_STATUS は、6_2 の IF 鏡像負例がこの規則で TISSUE_LEVEL まで通ると申告している。提示コードには、この既知リスクを明示的に止める追加ゲートがない。

**事実と推測の区別**

当該負例の通過実績は文書の申告であり、再実行していない。コードから確認できるのは、防御条件の欠如と、条件を満たす鏡像候補が TISSUE_LEVEL になり得ることである。

TISSUE_LEVEL は `accepted=False` のため、この問題だけで Workflow D の自動接続が許可されるわけではない。ただし、誤った組織整合を暫定合格として提示する危険が残る。

**修正案・改善案**

取得系で許される向きを明示メタデータとして管理し、許されない反転を拒否する。反転が実データで必要な場合は、一律禁止せず、組織の向きや独立した対応情報に基づく検証を追加する。既知の鏡像負例が NOT_ACCEPTED になることを事前固定した基準で確認する。

隣接切片の核近接を Safety Gate に戻す修正は、INTENT に反するため採用しない。

### 4. 【中】3状態の契約にない POINT_ONLY_FALLBACK が、自動採択・Workflow D 接続を許可される

**根拠**

- `workflow.py`：`decide()`

**事実**

**事実と推測の区別**

**修正案・改善案**

## 問題がなかった観点

- **TISSUE_LEVEL の accepted フラグ**  
  `_decide_adjacent()` は常に `accepted=False` を返す。`accepted_tissue_level` は別フィールドであり、`run_workflow()` の transform にも細胞レベルの accepted 値が引き継がれる。提示範囲に自動昇格処理はない。

- **TISSUE_LEVEL／NOT_ACCEPTED の Workflow D 接続拒否**  
  `check_handoff()` は accepted フラグと状態の許可リストを両方確認し、`to_workflow_c_artifact()` は不許可なら例外を送出する。TISSUE_LEVEL に accepted フラグだけを立てても、状態チェックで拒否される。提示された橋渡し経路に、両状態の自動接続は認められない。その他の呼び出し経路は資料外である。

- **隣接切片での核近接の扱い**  
  通常の画像判定経路では核評価は記録に留まり、TISSUE_LEVEL の条件には使われない。画像候補の核 ICP 結果も採用せず探索姿勢を保持しており、INTENT と整合する。

- **注釈利用時の自動採択抑止**  
  判定側は assisted 実行を要レビューに変更し、橋渡し側も `mode="automatic"` を要求する。

- **検証の独立性・指標の解釈の申告**  
  RESEARCH_STATUS は開発ペア由来の派生ケースを独立検証と主張せず、未使用実データが0件であることを明記している。象限チェックの実装は内部整合性の確認であり、提示資料から ground truth とする主張は認められない。

## 総評

最大の問題は、切片関係の来歴競合を判定へ反映できず、6_2 が同一切片用規則から自動採択へ進めることである。UNKNOWN 等も同じ規則へ流れるため、切片関係が確定しない場合の採択保留が最優先となる。

TISSUE_LEVEL を Workflow D へ自動接続しない防御は、提示コードでは成立している。一方、切片関係の修正だけでは既知の鏡像負例が暫定合格する問題が残る。メタデータ管理、鏡像への防御、判定状態の契約、対応する回帰テストを一体として整備する必要がある。
